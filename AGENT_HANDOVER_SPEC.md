# Personal Antigravity Handover & Master Architecture Specification

You are assisting with the **Carnegie Mellon University School of Computer Science Executive Education: Agentic AI Program** capstone project.

It solves a core enterprise compensation problem: bridging the gap between a **Reactive Offers and Counter-Offers Desk** and **Strategic Client Compensation Partners** so that Vice Presidents and Lead People Partners receive clear, verified, one-page talent decision briefs rather than raw spreadsheets.

## 2. Engineering for smaller and publicly available models

The CMU program requires building and testing with publicly accessible models via **OpenRouter**, **Google AI Studio**, or local **Ollama** inference. Smaller or faster models, such as Flash-tier models or local 7B to 12B parameter models, fail when asked to do raw spreadsheet math, track long unstructured histories, or invent multi-step plans in a single pass.

To make this system perform reliably on Flash-tier and open-weights models, enforce these four architectural patterns across every module:

### Pattern 1. Zero-math in token space
Never ask the LLM to compute a percentage change, percentile rank, compa-ratio, or budget balance. Every Python tool in `src/tools/` must return **pre-computed, deterministic JSON summaries** alongside explicit boolean risk flags:
- Bad tool output: 200 raw CSV rows of employee salaries and grant dates.
- Good tool output: A structured Pydantic dictionary containing `cohort_size: 42`, `cliff_count_gt_15pct: 14`, `median_compa_ratio: 0.84`, `manager_inversion_count: 2`, `remaining_budget_usd: 1450000`, and `policy_trigger_flags: ["HIGH_CLIFF_DENSITY", "COUNTER_OFFER_SPIKE"]`.

### Pattern 2. Two-tier modular model router
Implement a `ModelRouter` class in `src/models/router.py` that reads model IDs from `.env` and routes tasks by cognitive load:
1. **Fast / Tool-Calling Tier.** Default to a high-speed, low-cost model with strong structured output support, such as Gemini Flash via AI Studio or OpenRouter, GPT-5.6 Luna/Mini, or local `qwen2.5:7b` / `gemma3:12b` via Ollama. Use this tier for intent parsing, SQLite/Pandas tool calling, query rewriting for ChromaDB, and schema validation.
2. **Deep Reasoning / Synthesis Tier.** Default to a reasoning-capable model via OpenRouter or AI Studio, such as Gemini Pro / Thinking, DeepSeek-R1, or Claude Sonnet. Use this tier specifically for **Checkpoint 4.1 Tree-of-Thought branch evaluation** and **Checkpoint 5.1 Executive Narrative synthesis**.

### Pattern 3. Pydantic-enforced state and handoffs
Use explicit Pydantic schemas for agent state, tool inputs, tool outputs, and inter-agent messages. Instead of passing free-text chat history between agents, pass a typed `InvestigationState` object containing only verified metrics, retrieved policy chunk IDs, and structured branch scores. This prevents context window bloat on smaller models.

### Pattern 4. Deterministic verification gate
Before any response reaches the user interface, run a deterministic Python verifier (`src/guardrails/verifier.py`) that extracts every currency figure, percentage, and headcount integer from the LLM draft using regex and checks that each number exists in the current turn's tool output dictionary. If a number is hallucinated or a proposed budget allocation exceeds `remaining_budget_usd`, the verifier rejects the draft and returns an explicit correction prompt to the agent.

## 3. End-to-end roadmap across all 7 CMU checkpoints

Build the codebase progressively so each module extends the existing files without rewrites.

| Checkpoint | Module Focus | What to Build in Code & Report |
| :--- | :--- | :--- |
| **1.1** | Problem Framing & Initial Design | Submit the 645-word write-up and Mermaid architecture diagram in `checkpoints/checkpoint_1_1.md`. Due October 12. No code submission required yet. |
| **2.1** | Reasoning, Memory & Tool Use | Run `data/synthetic/generate_synthetic_data.py` to build `comp_insight_advisor.db`. Implement `src/tools/roster_tools.py` and `src/tools/offer_tools.py` plus short-term session state and ReAct tool-calling loop. |
| **3.1** | RAG & Retrieval Design | Index `docs/policies/compensation_governance_playbook.md` into ChromaDB (`src/rag/policy_store.py`). Chunk by policy section headers with metadata tags (`domain: reactive_vs_proactive`, `tier_rubric`, `inversion_rules`) so retrieval stays under 1,500 tokens per query. |
| **4.1** | Tree-of-Thought Integration | Build `src/reasoning/tot_planner.py`. When a cohort shows both high equity cliffs and declining offer acceptance, generate 3 strategic branches: (A) Adjust new-hire and counter-offer bands, (B) Targeted proactive retention grants for cliff-risk high performers, (C) Hybrid split. Score each branch deterministically on 3-year budget cost, retention coverage, and internal equity risk before selecting the best path. |
| **5.1** | Multi-Agent Architecture | Refactor into three specialized agents coordinated by an Orchestrator (`src/agents/`): 1. **Reactive Market & Offer Analyst** (queries offer/counter logs), 2. **Proactive Org Health Strategist** (queries roster cliffs, inversions, and budgets), 3. **Executive Partner Synthesizer** (combines both with ChromaDB policy rules into a VP brief). |
| **6.1** | Safety Guardrails & HITL | Implement `src/guardrails/verifier.py` (numerical hallucination check, PII/employee-ID redaction for executive summaries, budget cap enforcement) and a Human-in-the-Loop approval gate in the Gradio UI (`src/app.py`) for any Tier 3 exception or cross-team policy conflict. |
| **7.1** | Final Report & 8-10 Min Video | Run end-to-end evaluation suite (`tests/evaluate_agent.py`) measuring numerical accuracy, policy compliance rate, and latency across models. Package final report PDF and record demo walk-through. |

## 4. Quick start on the personal machine

python3 -m venv .venv
source .venv/bin/activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Generate the deterministic synthetic SQLite database and CSVs
python3 data/synthetic/generate_synthetic_data.py

# 4. Copy .env.example to .env and add your OpenRouter or Google AI Studio API key
cp .env.example .env
